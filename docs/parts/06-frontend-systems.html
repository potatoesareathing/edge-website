Part 5The frontend systems in depth

Six systems, each self-contained. Read the ones you plan to touch.

5.1  Navigation: four tabs, one page

Your site looks like it has four pages. It has one. All four sections exist in index.html from the moment it loads; switching tabs adds and removes a CSS class.

function showTab(name, push) {
  if (!TABS.includes(name)) name = TABS[0];              // unknown → About

  document.querySelectorAll(".tab").forEach(btn => {      // 1. update buttons
    btn.setAttribute("aria-selected", String(btn.dataset.tab === name));
  });
  document.querySelectorAll(".panel").forEach(p => {      // 2. show one panel
    p.classList.toggle("is-active", p.id === "panel-" + name);
  });

  if (push && location.hash !== "#" + name) {             // 3. update the URL
    history.replaceState(null, "", "#" + name);
  }
  window.scrollTo({ top: 0, behavior: "auto" });          // 4. back to the top
  if (window.__edgeHomeworld) window.__edgeHomeworld(name);// 5. tell the video
}

What this buys you, and what it costs

AdvantageCost
Switching tabs is instant — no network request, nothing to load. The first load is bigger, because all four sections arrive at once. At your size this is negligible.
No routing library, no server configuration for URLs. Search engines see one page with one title and description. Google cannot show "EDGE — Join" as a separate result.
Sharing …/#players works, and the back button behaves. Actually, it does not fully: history.replaceState replaces the current history entry rather than adding one, so the back button skips past tab changes. This is a deliberate trade — the alternative traps people who clicked four tabs behind four back presses.
ARIA and why those attributes are there

role="tablist", role="tab", aria-selected, aria-controls are accessibility markup. A screen reader announces "tab, 2 of 4, selected" instead of "button". initTabs() also implements left/right arrow navigation, because that is what a screen-reader user expects from anything calling itself a tablist.

If you add a fifth tab you must add all four attributes, or the site becomes harder to use for people who need it most. Procedure 11.4 has the full checklist.

5.2  The renderers

Eight functions turn EDGE into DOM. They share a shape worth recognising: read data → build nodes → replace the container's children.

const fill = (node, kids) => { if (node) node.replaceChildren(...kids); };

replaceChildren empties the container and inserts the new nodes in one step. This is why running a renderer twice cannot duplicate content — a real bug class in hand-written DOM code.

The pieces worth knowing about

  • Empty states are designed, not accidental. emptyState() at app.js:114 produces a lettered panel explaining what goes there. Your site launches nearly empty, so these are what most visitors will see first. They are treated as a first-class surface.
  • Dates are parsed manually (app.js:33). Writing new Date("2026-09-28") makes JavaScript interpret it as UTC midnight, which in India (UTC+5:30) is still the 28th — but for negative offsets it lands on the 27th. Splitting the string and building the date from parts avoids the whole class of off-by-one-day bug.
  • The countdown (app.js:410) ticks every second toward the nearest future deadline in EDGE.updates. It finds that deadline itself; you never configure it. Add an event with a future date and the countdown retargets.
  • Updates split themselves into upcoming and past by comparing dates to today. You do not archive anything manually.
  • The blog filters build themselves from whatever tag values exist in your posts. Invent a new tag and a new filter chip appears.

5.3  The design system

The site has one visual idea, stated in DESIGN.md: a hand-painted signboard. Painted boards, cream-white lettering, heavy ruled borders, and exactly one reserved primary action.

ComponentClassRule
Board.boardReplaces cards everywhere. A 3px outer rule with a thin inner rule set in from it. Depth comes from border weight and overlap — there are no soft shadows, no glass and no glow anywhere in the system.
Plate.plateThe buttons. They shift 1px on press, like something physical.
Primary plate.plate--primaryThe only solid white fill on the page. A white fill means "this is the primary action". If you put one on something else, that is a bug, not a style choice.

DESIGN.md also carries a Refused list — things deliberately held out, each a regression if it returns: eyebrow labels above headings, section numbers, uniform card grids as page structure, thick coloured one-sided borders, decorative grid backgrounds, gradient text, glass, glow, near-black with a neon accent, and animating layout properties.

Why a refusal list is worth more than a style guide

Style guides describe what to do and are ignored under deadline. A refusal list describes what not to do, and it is checkable: you can look at a change and ask "does this introduce something on the list?" It is how the site stayed coherent across many separate edits.

Responsive design

Media query

A block of CSS that applies only when a condition is true — usually a screen width. @media (max-width: 680px) { … } means "apply this on screens up to 680 pixels wide".

Your site has eleven, at four breakpoints: 900px (tablet layout), 680px (phones — the big one, section 20), portrait under 860px (the FAQ world's character framing), and landscape under 520px tall (phone held sideways). Two more respond to prefers-reduced-motion rather than size.

prefers-reduced-motion

An operating-system setting a person turns on if animation makes them ill — vestibular disorders are common and motion can cause genuine nausea. Your site checks it in CSS and in four places in JavaScript, and when it is on: the glitch effect is removed entirely, scroll reveals are disabled, the magnet is off, the background video is never even downloaded, and the portal is skipped in favour of going straight in.

This is not decoration. It is the difference between a site someone can use and one they cannot.

5.4  The homeworld video

The looping film behind the first screen of the About tab. Three rules govern it, all about not wasting a student's mobile data.

The crossfaded loop

The original cut hard at the join, producing a visible jump every 8 seconds. The shipped file is 7 seconds: its first second is a blend of the source's tail fading into its head, so the last frame and the first frame are one frame apart in the original timeline.

Measured, the junction differs by 6.6 RMS against 9.8 for ordinary adjacent frames mid-clip — the loop point is a smaller visual step than normal motion, so there is nothing to see. The re-encode also dropped the audio track and took the file from 7.9 MB to 3.9 MB.

Needs verification

The exact ffmpeg command used to produce the crossfade is not recorded anywhere in the project. If you need to re-cut a loop, you will have to rebuild the command. The technique is a blend=all_expr filter for video and acrossfade for audio. Procedure 11.2 includes a working command — test it before relying on it.

5.5  The animation layer

Three effects, one grammar. DESIGN.md is explicit that these are a deliberate system rather than scattered flourishes.

EffectWhereHow it works
Paint-on revealapp.js:805 Content wipes in left-to-right, the same gesture as the panel entrance — rather than the generic fade-and-rise. Uses an IntersectionObserver: the browser tells your code when an element scrolls into view, which is far cheaper than checking positions on every scroll event. Each element is unobserved after revealing, so it never re-hides.
Hover glitchapp.js:702 Two offset copies of a string flash for about 0.26s. initGlitch() copies each element's own text into a data-text attribute so CSS can draw the doubled copies. It must run last in init() — it reads text the renderers have just created.
Magnetic launcherapp.js:654 The Ask button leans toward the cursor within 140px, travelling 34% of the offset. It reads as the thing on the other side reaching for you.
Two performance rules this code follows

Only animate transform and opacity. These can be handled by the GPU without recalculating the page's layout. Animating width, padding, height or margin forces the browser to re-measure everything, every frame — that is what "jank" is. Two such animations shipped briefly in this project and were caught.

Never call getBoundingClientRect() in a mousemove handler. It forces the browser to compute layout immediately. The magnet caches the button's position and only re-measures on resize (app.js:661). Doing it per-event is exactly how a small flourish becomes a stuttering page.

The safety net, and the lesson behind it

setTimeout(() => {
  if (!document.querySelector(".rise.is-in")) {
    targets.forEach(node => node.classList.add("is-in"));   // show everything
  }
}, 2000);

The reveal effect works by hiding elements until the observer says otherwise. If the observer never fires, the page stays blank — the one failure a scroll reveal must not have. After two seconds, if nothing has revealed at all, everything is shown. It only triggers when the effect is already broken.

A hard-won rule: do not use requestAnimationFrame for correctness

requestAnimationFrame (rAF) asks the browser to run code before the next frame. It is the right tool for smoothing animation. It is the wrong tool for anything that must simply happen, because rAF does not fire in a backgrounded or throttled tab.

This bit the project three separate times: the FAQ drawer sat parked off-screen while still focusable; the scrim never updated; the portal handover never fired. All three are now driven by direct calls or by setInterval. The portal's audio ramp uses a 40ms interval specifically for this reason (portal.js:303) — whether sound is audible at all must not depend on rAF running.

5.6  Sound

js/sound.js plays a dry tick on press. Nothing is downloaded — the sound is generated using the Web Audio API: an oscillator whose pitch falls, a volume envelope that opens in 4 milliseconds and closes over 55, and a highpass filter to keep it a tick rather than a thud.

const VOICES = {
  tap:   { from: 1500, to: 620, peak: 0.028, len: 0.055 },  // chips, tabs, FAQ rows
  press: { from: 900,  to: 260, peak: 0.055, len: 0.085 }   // primary actions
};

Which control gets which voice is decided by two CSS selectors at sound.js:76, matched against whatever was clicked. This is called event delegation: one listener on the document rather than a listener per button, so anything rendered later from content.js is covered without rebinding.

Browsers refuse to play audio before a visitor has interacted with the page — an anti-annoyance rule. Here that condition is met by construction, because every trigger is itself a click.

To change the sounds

peak is volume (0.028 is deliberately quiet). from and to are the pitch sweep in hertz. len is the duration in seconds. To silence the site entirely, open the browser console and run EDGE_SOUND.mute(true) — or delete the <script src="js/sound.js"> line, which removes the feature cleanly.
