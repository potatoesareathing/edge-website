Part 7Hosting, deployment and the outside world

How your files get from your laptop to a student's phone, and every outside party involved on the way.

7.1  Git, GitHub and GitHub Pages — three different things

People use these names interchangeably. They are not the same, and understanding the difference makes deployment obvious.

Git

A program on your computer that records snapshots of your project. Each snapshot is a commit, with a message saying what changed and why. Git works entirely offline. It is your undo history, at project scale, forever.

GitHub

A website that stores a copy of your git repository in the cloud. It is your backup, your collaboration point, and — for you — your deployment mechanism. Your account is potatoesareathing; your repository is edge-website.

GitHub Pages

A feature of GitHub that takes whatever is committed on a chosen branch and serves it as a website. Yours is configured to serve the main branch from the root folder. It runs no code — it only hands out files.

7.2  What a deployment actually is

The commands you will actually use

CommandWhat it does
git statusWhat have I changed? Run this constantly. It is free and it prevents mistakes.
git diffShow me the exact lines I changed. Run before every commit.
git add -AStage everything for the next commit.
git commit -m "message"Take the snapshot.
git pushSend it to GitHub. This is the deployment.
git log --onelineHistory, newest first. Yours has 15 commits.
git checkout -- path/to/fileThrow away uncommitted changes to one file. Your undo.
git revert <hash>Undo a commit that is already pushed, by making a new commit that reverses it. Safe.
Two commands to avoid until you understand them

git reset --hard permanently discards uncommitted work with no undo. git push --force can erase history on GitHub, including other people's. Neither is needed for anything in this manual.

7.4  HTTPS, DNS and caching on your current host

HTTPS

Handled entirely by GitHub. Your repository reports https_enforced: true, so visitors arriving over plain HTTP are redirected. The certificate is issued and renewed automatically. Nothing to maintain — unless you add a custom domain, in which case you must wait for the certificate to be issued and re-tick "Enforce HTTPS".

DNS

You have none. GitHub owns github.io. The subpath /edge-website/ comes from the repository name.

Why the subpath works at all

Because every asset path in your site is relative — css/styles.css, not /css/styles.css. A leading slash means "from the domain root", which would resolve to github.io/css/styles.css and 404.

Rule: never start an asset path with a slash in this project. It will work in local preview and break in production, which is the worst kind of bug.

Caching

GitHub Pages sets its own cache headers and you cannot configure them. The rules in netlify.toml do nothing. In practice Pages serves assets with a ten-minute cache, which is short enough that stale files are rarely a problem — but when you do replace an image and still see the old one, add or bump a version marker:

<img src="assets/edge-mark.svg?v=3">   <!-- was ?v=2 -->

The browser treats a different query string as a different file. This is why every logo reference in your HTML already carries ?v=2.

One Pages-specific requirement

GitHub Pages runs files through Jekyll, a site generator, which ignores any file or folder whose name starts with an underscore. Your project has none, so it works. If you ever add _drafts/ or _assets/, those files will silently not publish. The fix is an empty file named .nojekyll at the repository root.

Part 8What happens if Claude disappears tomorrow

The honest answer: your website keeps running, unchanged, indefinitely. Nothing in it calls an AI service. But your ability to change it depends on things you should secure now.

8.1  What is genuinely at risk

ConcernReal riskWhy
The site stops workingNone No AI service is contacted at runtime. The chatbot is a keyword matcher running on the visitor's device. Delete every AI tool from your life and the site is unaffected.
You cannot deployNone Deployment is git push. That is a standard tool that predates all of this and will outlive it.
You cannot make content changesLow content.js is plain data with comments. Part 11 gives you the procedures.
You cannot fix a visual bugMedium CSS is learnable and the browser's inspector teaches it to you interactively. Part 12 covers the method.
You cannot modify portal.jsHigh Shader programming is a genuine specialism. Realistic mitigation: do not modify it. It works, it is documented, and it degrades gracefully. If it ever breaks beyond repair, delete the script tag — the FAQ world still opens, just without the effect.
You lose the video sourcesHigh The two -source.mp4 files are gitignored and exist only on your laptop. A disk failure loses them permanently. Back them up today.

8.2  What to secure this week

Accounts and credentials

  • GitHub (potatoesareathing) — the critical one. Turn on two-factor authentication. Write down the recovery codes and keep them somewhere physical. If the club will outlive you, add a second committee member as a collaborator now.
  • Netlify (aaliyahaijaz2006) — no longer needed. Keep the login noted in case you return to it.
  • Supabase — when you create it, record which email owns it. A project tied to a graduating student's personal account is a club asset that walks out the door.
  • Domain registrar — if you ever buy a domain, this becomes as critical as GitHub, and it has a renewal date that will lapse silently.

Files that exist in only one place

  • assets/video/homeworld-source.mp4 and faq-world-source.mp4 — the originals before the crossfade edit.
  • _archive-v1/ — the first version of the site.
  • The original logo artwork the SVGs were traced from.

Copy all of these to cloud storage or an external drive. They are not in git and GitHub does not have them.

Knowledge that lives only in the documentation

Four files in your repository carry reasoning that is not recoverable from the code: README.md (how to set up and deploy), ARCHITECTURE.md (thirteen invariants — rules that must stay true), DESIGN.md (why it looks this way, and a record of past mistakes), PRODUCT.md (who the site is for). Plus this manual.

Keep them updated. Documentation that lies is worse than none, because you will trust it.

8.4  The recovery drill

Do this once, now, while nothing is wrong. It takes fifteen minutes and it converts "I hope I could recover" into "I have recovered before".

cd ~/Desktop
git clone https://github.com/potatoesareathing/edge-website.git edge-test
cd edge-test
node serve.js
# open http://localhost:8790 — the whole site should work

If that works, you have proved that GitHub alone is enough to rebuild your entire project on any computer. Delete the test folder afterwards.
