4.2  Safe, careful, and dangerous

Judge every file by one question: if I get this wrong, how much breaks and how obviously?

FileVerdictWhy
js/content.jsSafe Designed to be edited. It is data, not logic. The worst realistic mistake is a missing comma or quote, which empties the site — loudly and obviously, and fixed by undoing your change. Make 90% of your edits here.
The four .md docsSafe Not served to visitors. Cannot break anything. Keep them current; they are your memory.
index.htmlCareful Safe to change visible words. Dangerous to change or remove an id — JavaScript finds elements by id, and a renamed id means a renderer silently does nothing. Also do not reorder the script tags (3.2).
css/styles.cssCareful Can only break appearance, never logic — but appearance breaks can make the site unusable (an invisible button is a broken button). The specificity trap in 4.6 has bitten this project twice.

js/join.jsCareful Handles real student data. A broken validation rule means bad data or a form nobody can submit. Always test both paths (Member and Roster) after touching it.

4.3  What each file is responsible for

index.html — the skeleton and the sockets

Three jobs. First, it declares the page's metadata: the title, the description search engines show, the viewport tag that makes the site work on phones at all. Second, it lays out the visible structure. Third, and most importantly for you, it provides empty containers with ids for JavaScript to fill.

Its structure, top to bottom:

  • .homeworld — the background video layer, deliberately placed outside everything else. The comment at line 16 explains why: the panel entrance animation uses clip-path, and a clip-path on a parent also clips fixed-position children. Nesting the video inside would have cropped it.
  • .topbar — logo and the four tab buttons.
  • main.shell — four <section class="panel"> elements, one per tab. Only one has the class is-active at a time.
  • .footer
  • #portalCanvas, #faqVideo, .ask-fab, #faqWorld — the Ask EDGE system, all outside main because it is not part of any tab.
  • The six script tags.

4.5  The dangerous lines in .gitignore

assets/frames/
assets/jinn_punch.original.mp4

These exclude AI-generated footage of a Tekken character and the frames cut from it. It is third-party intellectual property, it is not used by the site, and it must not be published. It was once accidentally put online, because a deploy command that uploads a folder ignores .gitignore entirely.

Two rules that follow from that incident
  1. Never deploy by uploading a folder. Deploy by pushing to git. Git only publishes what is committed, so .gitignore is actually enforced.
  2. Deleting a line from .gitignore can publish a file on your next commit. Before removing any line, look at what it is hiding.

Note also that git history is permanent: once something is committed and pushed, deleting it later does not remove it from the repository's history. Anyone can recover it. Getting this right the first time is the only reliable approach.

The file also excludes the two video source files (homeworld-source.mp4, faq-world-source.mp4). Those are the originals before the crossfade edit. They exist only on your computer. They are not backed up anywhere. If you ever need to re-edit the loops, you need them — copy them to cloud storage.

4.6  The CSS trap that has bitten this project twice

When two CSS rules target the same element, the browser picks the winner by specificity — a score based on how precisely the selector names the element, not on which rule appears later.

table.board-table { min-width: 640px; }   /* element + class = stronger */
.board-table     { min-width: 0;     }   /* class only     = weaker  */

The second rule loses even though it comes later and sits inside a phone media query. This is exactly what happened: the leaderboard stayed 640px wide on a 375px phone, and nothing in the browser reported an error. The fix was to match the weight:

table.board-table { min-width: 0; }

The same mistake in the opposite direction broke the logo. A blanket rule img[src*="edge-mark.svg"] was added to control the mark's size; an attribute selector outranks a plain class, so it overrode every component's own height and collapsed the logos.

The habit to build

Before writing a CSS override, find the rule you are trying to beat and copy its selector shape. If the original says table.board-table, your override says table.board-table. Verify in the browser's element inspector, which shows overridden rules struck through — if your new rule appears struck through, you lost on specificity.

4.7  Where secrets should live

A hard truth for a static site: there is nowhere truly safe. Anything the browser can read, a visitor can read. You have no server and no build step, so there is no mechanism to hide a value.

This means:

  • The Supabase anon key goes in content.js in plain sight. That is by design — it is called "anon public" because it is meant to be public.
  • The Supabase service role key must never appear in this project, in any file, ever. It bypasses all security rules. It belongs only in the Supabase dashboard.
  • Your GitHub password and any access tokens live in your machine's credential manager, never in a file in the repository.
  • If you ever need a genuine secret in a web request — an email service key, a payment key — that request must be made by a backend, not by the browser. There is no workaround.
