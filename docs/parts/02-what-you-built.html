Part 1What you actually built

Before any detail, get the shape of the thing in your head. Your site is simpler than you probably fear and more unusual than you probably realise.

1.1  The five honest sentences

  1. Your website is 22 files. One HTML file, one stylesheet, six JavaScript files, four media files, four documents, and a few configuration files. That is all of it.
  2. It has no dependencies. There is no package.json, no node_modules folder, no framework. Nothing was downloaded from anyone to make it run. This is rare and it is a large part of why it will still work in five years.
  3. It has no build step. The files you edit are the exact files a visitor's browser receives. Nothing compiles, bundles, transpiles or minifies. What you see is what ships.
  4. It has no backend of its own. No server of yours runs any code. The site is static files handed out by GitHub. The one piece of server-side work it wants to do — storing registrations — is delegated to an outside service that is not yet connected.
  5. All of its content lives in one file. js/content.js holds every piece of text, every roster, the leaderboard, the events, the FAQ answers. You can run the club's website for a year without opening any other file.

1.3  What your site is not

Half of understanding a system is knowing what it does not contain. People will assume your site has these things because most sites do. It does not:

Thing it does not haveWhat that meansWhy it is fine (or not)
A framework
(React, Vue, Next.js)		 No library imposes structure on your code. You wrote plain JavaScript that talks to the browser directly. Fine, and a real advantage. Frameworks break as they upgrade. Plain JavaScript from 2015 still runs today. Nothing here will rot.
A build step Nothing turns your source into different output files. Edit a file, push it, it is live exactly as written. Fine. You lose automatic minification (smaller files) and cannot use newer syntax that old browsers reject. Neither matters at this size.
A backend No code of yours runs on a server. Nothing can happen on your site while nobody is looking at it. Fine for now. The moment you need email notifications, an admin page, or scheduled jobs, you will need one. Part 13 covers what that would take.
Accounts or logins No authentication — no way for anyone to prove who they are. Nobody signs in, so there is nothing to sign into. Fine, and a relief. Authentication is where most beginner sites get breached. You cannot leak passwords you never collected.
A database you run Rosters, leaderboard and events are hardcoded in js/content.js and change only when you edit and push. Fine at club scale. Editing a file and pushing takes two minutes. A database would be worth it at hundreds of rows changing weekly.
Analytics Nothing counts visitors. You have no idea how many people use the site. A genuine gap, and a privacy win. Part 9 covers adding a privacy-respecting counter if you want one.
Error monitoring If the site breaks for a visitor, nothing tells you. You only find out if somebody complains. A genuine gap. The most likely failure — the portal on an old phone — is already handled gracefully in code, but you would not know.
A custom domain The address is potatoesareathing.github.io/edge-website/. You do not own a domain name, so there is no DNS to configure. Fine, but weak for a club. Part 11.17 covers buying edgeruas.in or similar and pointing it here.
A favicon No little icon in the browser tab. There is no favicon.ico in the project. Small but visible gap. Five-minute fix, Part 11.18.
robots.txt / sitemap.xml No instructions for search engines. Google will still find and index the site; it just has no guidance. Minor. Worth adding once the content is real.
The thing to take from this

You did not build a small version of a complicated thing. You built a genuinely simple thing that happens to have two sophisticated pieces in it (the WebGL portal and the video system). Simple systems are maintainable by one person. Keep it that way: every dependency you add is a thing that can break while you are not looking.
