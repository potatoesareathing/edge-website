10.3  Things that work but are worth knowing about

  • The back button skips tab changes. history.replaceState replaces rather than adds history entries. Deliberate, but it surprises people.
  • The leaderboard hides two columns on phones. W and L are dropped below 680px because they cost 150px of width and are derivable from the record. The full table is there on a laptop.
  • A comment in portal.js says "two triangles" but the code uploads three vertices and draws one oversized triangle covering clip space — a standard trick that avoids a seam down the diagonal. The comment is slightly wrong; the code is correct.
  • serve.js is published but never runs. GitHub Pages executes nothing. Harmless, but do not expect it to do anything in production.
  • EDGE_ASK and EDGE_SOUND are exposed but unused. Deliberate hooks for features not yet built.

Eighteen procedures for the jobs you will actually do, written against your real files. Every one ends the same way, so learn that ending once.

The ending, used by every procedure below

11.2  Replace a video

The hard part is not swapping the file; it is the crossfade that makes the loop invisible.

  1. Keep your new source out of the repo: name it homeworld-source.mp4, which .gitignore already excludes.
  2. Produce a crossfaded loop. For an 8-second source producing a 7-second loop: 
    ffmpeg -i homeworld-source.mp4 -filter_complex ^
 "[0:v]trim=0:1,setpts=PTS-STARTPTS[head]; ^
  [0:v]trim=7:8,setpts=PTS-STARTPTS[tail]; ^
  [tail][head]blend=all_expr='A*(1-T/1)+B*(T/1)'[fade]; ^
  [0:v]trim=1:7,setpts=PTS-STARTPTS[mid]; ^
  [fade][mid]concat=n=2:v=1[out]" ^
 -map "[out]" -an -c:v libx264 -crf 26 -pix_fmt yuv420p homeworld.mp4
    Needs verification — this reconstructs the technique; test the output before shipping.
  3. Check the size. Target under 4 MB. Raise -crf (28, 30) to shrink it.
  4. Extract a matching poster: 
    ffmpeg -i homeworld.mp4 -ss 2 -vframes 1 -q:v 4 homeworld-poster.jpg
  5. Put both in assets/video/, replacing the old ones. Filenames must stay the same, or update VIDEO_SRC at app.js:735.
  6. Test the loop: watch it for 30 seconds. If you can see where it restarts, the crossfade failed.
  7. [preview, commit, push]

What breaks: the FAQ world's video must keep its audio track — the portal ramps its volume to 40%. Adding -an to that one would silence the feature.

11.3  Add a page

Your site has no pages, only tabs. Adding a genuine second HTML file would break the single-page model. Add a tab instead — 11.4.

If you truly need a separate URL (for sharing, or for search engines), create rules.html as a copy of index.html with the body replaced, keeping the same stylesheet and script tags. Be aware you now maintain the header and footer in two places, which is how sites drift out of sync.

11.4  Add a navigation tab

Four edits, in order. Miss one and the tab appears but does nothing.

  1. index.html — add the button next to the others, copying every attribute: 
    <button class="tab" role="tab" id="tab-rules" aria-controls="panel-rules"
        aria-selected="false" data-tab="rules">Rules</button>
  2. index.html — add the panel inside <main>: 
    <section class="panel" id="panel-rules" role="tabpanel"
         aria-labelledby="tab-rules" tabindex="0">
  <div class="panel__head"><h1 class="painted">Rules</h1></div>
  <div id="rulesBody"></div>
</section>
  3. app.js:45 — add the name to the router: 
    const TABS = ["about", "players", "updates", "join", "rules"];
  4. Content — either write it into the HTML directly, or add a rules key in content.js and a small renderer in app.js called from init().
  5. [preview, commit, push]

What breaks: forget step 3 and clicking the tab does nothing — showTab falls back to About because the name is not in TABS. Forget the ARIA attributes and the tab is unusable with a screen reader.

11.5  Add a blog post with a photo

  1. Optimise the image first. A phone photo is 4–8 MB. Resize to about 1600px wide and save as JPEG at quality 80 — usually 200–400 KB. Use Squoosh (squoosh.app), GIMP, or: ffmpeg -i big.jpg -vf scale=1600:-1 -q:v 5 small.jpg
  2. Create assets/blog/ if it does not exist. Use lowercase names with hyphens.
  3. Add the entry at the top of EDGE.blog: 
    {
  type:  "post",
  title: "Valorant tryouts — day two",
  date:  "2026-10-04",
  tag:   "Events",
  media: "assets/blog/tryouts-day2.jpg",
  alt:   "Players at the tryouts, seated at the lab machines",
  body:  "Twenty-two players across four hours.",
  credit: "Ananya R"
}
  4. [preview, commit, push]

What breaks: a wrong media path shows a broken image. Skipping alt makes the post invisible to screen readers. Skipping optimisation is the single most common way a fast site becomes slow.

For an Instagram post instead, use type: "instagram" and paste the post URL into url. No API key is needed. An empty url is skipped silently.

11.7  Change what the chatbot knows

Do not edit faq-bot.js. Edit EDGE.faq.entries in content.js.

To improve an answer the bot already gives

Edit the a string. Nothing else changes.

To fix a question the bot misunderstands

Find the entry that should have matched and add the words the person actually typed to its keywords, including slang and misspellings.

To add a whole new question

{
  q: "Can I join two teams?",
  a: "No. You can try out for more than one title, but you play for one roster per season.",
  keywords: ["two", "multiple", "both", "second", "another", "team", "teams", "switch"]
}

It appears in the chat and in the static "Every question" list automatically.

If the bot answers too eagerly or too rarely

Only then touch faq-bot.js:96: CONFIDENCE_BAR = 1.4. Raise it to make the bot more cautious, lower it to make it guess more. Change it in steps of 0.1 and test.

What breaks: piling keywords onto one entry makes it swallow unrelated questions. If one answer starts appearing for everything, that entry has too many generic keywords.

Do not "fix" logo sizing with a blanket CSS rule

Adding img[src*="edge-mark.svg"] { height: … } looks like a tidy global fix. An attribute selector outranks a class, so it overrides every component's own height and breaks the mark everywhere at once. This has already happened once. Each use sets its own height and lets width follow.

11.14  Turn the registration form on — do this first

The most important procedure in this manual. About twenty minutes.

  1. Create the project. supabase.com → sign up → New project. Choose the region nearest India. Save the database password somewhere safe; you will rarely need it but cannot recover it.
  2. Create the table. SQL Editor → New query. Paste the entire contents of supabase-schema.sql → Run. It creates the table, the constraints, and the security policy.
  3. Copy the two values. Project Settings → API. You need the Project URL (https://abcdefgh.supabase.co) and the anon public key.
  4. Paste them in at content.js:126: 
    backend: {
  mode: "supabase",
  supabase: {
    url:      "https://abcdefgh.supabase.co",
    anon_key: "eyJhbGciOi...",
    table:    "registrations"
  }
}
  5. Verify the security — do not skip this. Run the two commands at the bottom of supabase-schema.sql. The insert must succeed. The select must return an empty list []. If it returns rows, RLS is not protecting you: stop, fix it, and do not go live.
  6. Test end to end. [preview, commit, push], then submit a real registration on the live site. Confirm the row appears in the dashboard. Delete the test row.
  7. Check the console. The warning "The join form is not connected yet" should be gone.
Anyone who registered before this

Their data is in localStorage on their own device and will be sent automatically the next time they open the site — flush() runs on every page load. Anyone who never returns is lost. If you ran a club fair before connecting, assume those registrations are gone and collect again.

11.15  Self-host the fonts

Removes a third party from every page load, makes the site work fully offline, and avoids the flash of fallback text.

  1. Download Chakra Petch and Archivo from fonts.google.com (both are open source).
  2. Put the .woff2 files in assets/fonts/.
  3. Add to the top of styles.css: 
    @font-face {
  font-family: "Chakra Petch"; font-weight: 700; font-display: swap;
  src: url("../assets/fonts/ChakraPetch-Bold.woff2") format("woff2");
}
    Repeat for each weight you use: Chakra Petch 500/600/700, Archivo 400/500/600.
  4. Delete the three <link> tags for Google Fonts from index.html.
  5. [preview, commit, push]

What breaks: miss a weight and that text silently falls back. Check headings, buttons and body text after.

11.16  Add a second portal world

The portal was built to be reused. To send Players into its own dimension:

  1. Produce a crossfaded loop for it (11.2) and add it as assets/video/players-world.mp4 plus a poster.
  2. In index.html, copy the <video class="portal-src"> element, giving it a new id. Copy the <section class="world"> block and give it a new id and its own content.
  3. In app.js, copy initAsk() to initPlayersWorld(), changing the four element ids and the video path. Call it from init().
  4. [preview, commit, push]
One real constraint

portal.js holds a single set of module-level state — one video, one origin, one progress. Two worlds can exist, but only one may be open or peeking at a time. Opening a second while the first is peeking will confuse it. If you need genuinely concurrent portals, the module must be refactored to create instances.

11.17  Connect a custom domain

  1. Buy the domain (Namecheap, Cloudflare, or an Indian registrar for a .in). Budget about ₹800–1,500 per year and note the renewal date.
  2. At the registrar, add DNS records pointing at GitHub: 
    Type   Name   Value
A      @      185.199.108.153
A      @      185.199.109.153
A      @      185.199.110.153
A      @      185.199.111.153
CNAME  www    potatoesareathing.github.io
    Verify these IPs against GitHub's current documentation — they change rarely but they do change.
  3. GitHub repo → Settings → Pages → Custom domain → enter it → Save. This creates a CNAME file in your repository.
  4. Wait for DNS to propagate (minutes to 24 hours), then tick Enforce HTTPS.
  5. Your asset paths already work, because they are relative. Moving from a subpath to a domain root changes nothing in your code.

What breaks: forgetting to re-tick Enforce HTTPS leaves the site on plain HTTP. A lapsed renewal takes the site down and frees the name for anyone to buy.
